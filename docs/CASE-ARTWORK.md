# Case artwork

How to make art that lands correctly on the 3D game case, and what the
launcher does when a title has none.

The template to lay a sleeve out on is **`docs/case-artwork-template.png`**,
generated by `docs/make-placeholder-art.py`. The numbers below and the numbers
in that script are the same numbers; change one and regenerate.

## The sleeve

One printed sheet wraps the whole case: back cover, spine, front cover.

| | mm | px at 9.01 px/mm |
|---|---|---|
| Whole sheet | 284 x 190 | 2560 x 1712 |
| One cover | 135 x 190 | 1217 x 1712 |
| Spine | 14 x 190 | 126 x 1712 |
| Bleed | 3 all round | 27 |
| Safe area | 5 inside the trim | 45 |

Laid out left to right: **back cover | spine | front cover**. The front cover
is the right-hand panel, which is why it occupies `u > 0.52` in the model's
UVs. Art must run into the bleed; text must stay inside the safe area.

## What the launcher actually takes

The renderer dresses the case from one sheet, but `CaseArt` takes the panels
separately and composes the sheet itself (`case_art::wrap`):

| Field | What it wants |
|---|---|
| `front` | One cover panel, 135 x 190 proportions |
| `back` | One cover panel, 135 x 190 proportions |
| `spine` | A tall thin strip, 14 x 190 proportions |
| `disc` | A square, mapped 0..1 across the disc face |

**Hand a cover slot a whole 284 mm sleeve and it gets letterboxed into the
panel.** That is the easiest mistake to make here and it looks almost right,
which is worse. The samples in `app/assets/dvd-case/textures/` are named for
which slot they belong to: `cover-front-sample.jpg` and
`cover-back-sample.jpg` are panels, `case-wrap-sample.jpg` is the whole sheet
and is *not* a cover.

Where artwork comes from in normal use is the person's own RetroMedia
library — `box2d` for fronts, `boxback` for backs, `spine`, and `discs` — not
from any third-party art site. A title with no artwork gets covers drawn from
its name by `case_art::drawn_cover`.

## The model

`docs/make-case-model.py` builds the case from nothing:

    blender -b -noaudio --python docs/make-case-model.py

It writes `app/assets/dvd-case/case.glb`. There is no imported model and no
third-party source: the geometry is written out vertex by vertex, with no
booleans and no modifiers, because a cutter that overlaps its target deletes
the whole case and does it silently in a headless build.

Node names are the contract with `fz1_3d.rs`:

| Node | What it is |
|---|---|
| `CaseShell` | base half, spine and inner walls |
| `CaseLid` | front cover, origin **on the hinge** so a rotation about X opens it |
| `Wrap` | the sleeve's back cover and spine, static |
| `WrapLid` | the sleeve's front cover, same hinge origin, swings with the lid |
| `CaseDisc` | the disc's printed label |
| `DiscRing` | the unprinted outer rim |
| `DiscHub` | the clear centre hub |

`Fz1State::lid` runs 0 (shut) to 1 (open); the GUI eases it toward `lid_goal`,
which is 1 whenever a case is being looked at. Fully open is 170 degrees.

## Two traps worth knowing before editing the model

**Winding decides whether a print reads mirrored.** A face wound so its normal
points away from the viewer shows its back, and a back-facing print is
mirrored. No UV change fixes it — chasing the UVs instead will only turn a
mirrored label into a mirrored, rotated label. Check the normal first.

**The hinge side decides which way the sheet reads.** The spine sits at `+Y`
in the model, which puts it on the viewer's left when the case is shut, as a
real case has it. Moving the hinge to the other edge mirrors every cover,
because the sheet then wraps the other way round.

The disc label's square UV follows the FZ-1 platter's own mapping, written in
Blender's axes: the exporter turns `(x, y, z)` into glTF `(x, z, -y)`, so the
platter's `v = 0.5 + z/2r` is `0.5 - y/2R` here.

## Checking a change

    cargo run --release --example case_shot -- /tmp/shots 900 900

Eight views per sample title, including `open` and `half-open`. Look at them.
Every fault in this model — a mirrored cover, a letterboxed panel, a label
rotated a quarter turn, a disc lit from the wrong side — passed a clean build
and was only ever caught by looking at the picture.
